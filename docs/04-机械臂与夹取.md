# 04 机械臂与夹取

机械臂是 10-15 才接入的，却是后面改动最密的部分：从"示教录制回放"一路收敛到
"点动 + 上电初始位 + 一键放块宏"。本篇如实记录这条收敛过程。

---

## 四路舵机与限位标定

### 功能描述

四个舵机接 **TIM4** 四通道，50Hz，脉宽 500~2500µs（0°~180° 舵机）：

| 通道 | 引脚 | 关节 | 软限位（µs） | 点动速度（µs/s） |
|---|---|---|---|---|
| ch0 | PB6 (TIM4_CH1) | 肩（大臂） | 1082 ~ 1800 | 600 |
| ch1 | PB7 (TIM4_CH2) | 肘（小臂） | 700 ~ 2500 | 700 |
| ch2 | PB8 (TIM4_CH3) | 腕 | 630 ~ 2390 | 700 |
| ch3 | PB9 (TIM4_CH4) | 夹爪 | 570 ~ 1330 | 900 |

所有运动都是"改目标值 + 每拍朝目标走一小步"（`arm_move_tick()`），所以是平滑走过去，不是瞬移。
每一步的速度即上表的 µs/s；按住 L1 为 1/3 速、R1 为 3 倍速。

### 开发历程

- 10-15 21:20 队友提交 `983eb4d`，带来 628 行的 `servo.c`（软限位 + 缓动）和 659 行的 `teach_only.c`
  （示教录制 + Flash 存取），并把链接脚本 **FLASH 64K→62K**，让出最后 2 页（`0x0800F800`，2KB）存录制数据。
- 10-16 13:20 夹爪到货先单测，实测脉宽表：**580~590µs 完全闭合、600µs 留 6mm 小孔、650~700µs 最佳抓取、
  1000µs 基本全开**。要求舵机"慢慢动"（缓动），这一条决定了点动速度不能太高。
- 10-16 审查队友代码时定位到一个真 bug：**夹爪开机一直堵转**——`servo.c` 里 `oc.Pulse = 1500`
  被 `servo_hw_init()` 直接下发到四路 CCR，上电瞬间全部输出 1.5ms 并保持。
  改法是"上电先松劲，按 `SELECT+START` 才通电"。
- 10-19 凌晨三轮现场标定（00:19 / 00:22 / 00:29）。前两轮的坑：
  ① 限位一个都没记下（`△/×` 必须闪 4 下才算记上，灯不闪就是没记）；
  ② `t_sv_span_ms = 13100` 被误当成"标定速度"（里面含人工停顿，真实速度 20 = 1000µs/s）。
  第三轮四路全部记完，确认都是 180° 舵机（0.09°/µs 粗算，未用量角器）。
- 10-19 19:24 用户要求"记录新一轮大臂的限位"：重测得 **1072µs = 最高、1372µs = 最低**
  （行程仅约 300µs ≈ 27°）。软限位内收 10µs → `ARM_US_SH_MIN = 1082`；
  最低方向按现场机械允许放到 `ARM_US_SH_MAX = 1800`（实测最低点 1372，用户手动放开到 1800）。
- 一个反复出现的坑：**限位改完必须抬版本号**。软限位存在 `.persist` 里，`arm_init()` 的逻辑是
  "magic 有效就沿用上次手调的值"，不换版本号的话新默认值永远不生效——所以 `ARM_MAGIC` 从
  `ARM1` 一路抬到现在的 `0x41524D34`（"ARM4"）。

## 示教录制回放 → 放弃

### 功能描述（历史）

早期实现是"按一次键拍一帧快照"：把四路当前脉宽 + 与上一帧的时间间隔存进数组（最多 32 帧），
回放时按帧改目标，靠 `arm_move_tick()` 平滑走过去。它**不是连续轨迹录制**，而是关键帧序列。

### 开发历程

- 10-15 接入时实现，按键是 `R2+△` 开始/停止录制、`R2+×` 记一个点、`R2+○` 试回放。
- 10-18 用户要求"先把和舵机相关的所有代码删除，就留下麦轮运动学"，`servo.c`、`teach_only.c`、
  `diag.c` 整批移出工程，旧文件归档到 `_removed_servo_20261018/`。
- 之后重写的 `arm.c` 里又短时间恢复过录制/回放，10-19 用户提出真实需求后彻底删除：
  "抓方块时各舵机状态每次不同，但回归放入的末态是一致的"——既然只要末态，就不需要整条轨迹。
- 教训：**通用功能（录制回放）不如专用功能（一键放块）**。前者要人记、要调、要试；
  后者一个键解决比赛里唯一的重复动作。

## 上电初始位（抓取姿态）

### 功能描述

`SELECT + START` 通电时，四路直接走到"钩爪完全闭合的抓取姿态"（`arm.h` 常量）：

```c
ARM_US_INIT_SH 1082   /* 肩：最高点（实测值） */
ARM_US_INIT_EL 2500   /* 肘：最里 */
ARM_US_INIT_WR 2004   /* 腕：爪口朝下 */
ARM_US_INIT_GR 570    /* 爪：完全闭合 */
```

### 开发历程

- 需求来自"不想每次上机都记录一次"，用户原话的意思是要一个**固定的默认初始位置**，
  上电即到位、不用现场摆。
- 21:03 现场摆出姿态后逐路读脉宽（`read_vars.ps1` 读 `t_arm_now`）得到上面四个数，写死成常量。
- 设计取舍：**上电默认松劲**（`SELECT+START` 才通电）。如果一上电就通电追位，
  机械臂可能还在包装/收纳姿态，舵机会硬顶着把结构扭坏。这是 10-16 堵转 bug 的直接教训。

## 放块宏（`R2 + R1`）

### 功能描述

一次按键完成"放块"：**记住当前姿态 → 走到放块位 → 前三轴到位后张爪丢块 → 回到按键之前的姿态**。

```c
ARM_US_PUT_SH 1082  ARM_US_PUT_EL 2500  ARM_US_PUT_WR 2004   /* 放块位（与初始位同一点） */
ARM_US_PUT_GR_OPEN  1330    /* 张爪到全开 */
ARM_PUT_HOLD_MS     400     /* 张爪保持 400ms，保证方块落下 */
ARM_PUT_ARRIVE_US   8       /* 到位判据：|当前 - 目标| ≤ 8µs */
ARM_PUT_TIMEOUT_MS  6000    /* 安全超时：6s 还没到位就放弃 */
```

状态机四态：`PUT_IDLE → PUT_MOVE（三轴走向放块位） → PUT_OPEN（张爪、保持） →
PUT_BACK（四路回到按键前姿态）`。宏运行期间其它按键被忽略，防止半途被点动打乱。

### 开发历程

- 需求原话（10-19 夜）：拾起方块后按 `R2+R1` 自动回到那个位置，**前三个都到位之后爪子才自动开启丢块**，
  然后回到按 `R2+R1` 之前的舵机状态。
- 先把"末态记忆"做成 Flash 持久化（写 `0x0800F800` 最后一页、magic + 校验和），
  烧录验证 `home_ok=1`。随后用户提出更简单的诉求（固定初始位、不想每次记录）→ 整套 Flash 代码删掉，
  改回编译期常量：**能用常量表达的，不要引入持久化存储**。
- 三个边界条件都是现场讨论定下来的：初始位与放块位目前是同一个点；张爪到 1330（全开）；
  放完回按键前的四路状态（爪子重新闭合，方便下一次抓）。
- 爪到位判定用 8µs，是因为舵机没有角度反馈，只能靠"目标 vs 当前指令值"收敛；真实机械到位会有滞后，
  所以张爪后额外保持 400ms。

## 机械臂按键与安全策略

### 功能描述

| 按键 | 动作 |
|---|---|
| ↑ / ↓ | 肩抬 / 肩落（脉宽变大是往下，所以按键方向已对调成"↑ = 抬起"） |
| ← / → | 肘收 / 肘伸 |
| △ / × | 腕上 / 腕下 |
| □ / ○ | 爪闭合 / 爪张开 |
| 按住 L1 / R1 | 点动 1/3 速 / 3 倍速 |
| SELECT + START | 四路通电 / 松劲 |
| R2 + R1 | 放块宏 |
| START | 整车急停（底盘停 + 臂松劲，灯慢闪） |

### 开发历程

- 10-18 15:55 用户"按 L1 会松劲…改成默认不松劲，按 start 松"→ 安全策略**反转**为"默认通电保持"，
  避免手一离开手柄机械臂就掉下来。
- 10-19 01:05~01:56 试做 L2 两连杆逆解模式（方向键直接给 x/y、爪竖直向下），撞上
  "2500 还没到…要越过 2500 到 500 才行？可这样不合法"的硬限位问题，
  加上肩只有约 28° 行程、可达区是窄月牙，实测不如手动点动 → 放弃，代码整段删除。
  结论写进本文档：**F103 无 FPU、舵机无角度反馈、比赛只需要 3~4 个固定姿态，实时逆解没有收益。**
- 10-19 22:48 最后一轮精简：删掉录制/回放、限位微调（`R2+↑/↓` 等）、方向对调按键，
  `arm.c` 从 21KB 缩到约 13KB，只保留"点动 + 上电初始位 + 放块宏"。方向改为代码里固定，
  不再给现场对调的入口——少一个能调错的地方。
