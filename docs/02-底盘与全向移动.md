# 02 底盘与全向移动

底盘是整个项目里改动次数最多的部分：10-11 从零写出第一版、10-12 做出全向移动、10-19 又一次从零重构。
本篇按时间顺序记录三次迭代。

---

## 电机驱动与 PWM 时基（第一版）

### 功能描述

四个 **TT 减速直流电机**，每个两路 PWM（正/反转），由 3 片 **DRV8833** 双 H 桥驱动：

| 轮子 | 引脚 | 定时器 |
|---|---|---|
| 左前 FL | PA0 / PA1 | TIM2_CH1 / CH2 |
| 右前 FR | PA2 / PA3 | TIM2_CH3 / CH4 |
| 左后 RL | PB0 / PB1 | TIM3_CH3 / CH4 |
| 右后 RR | PA8 / PA11 | TIM1_CH1 / CH4 |

代码分四层、依赖单向：`app → chassis → motor`、`app → ps2`。
`motor.c` 只负责"某个轮子给多大速度"，`chassis.c` 负责麦轮逆解，`app.c` 负责读手柄和流程。

第一版 PWM 时基：**PSC=0 / ARR=3599 → 72MHz / 3600 = 20kHz**（3600 步，占空比分辨率 0.05%）。
当时对比过 PSC=71 / ARR=49（只有 50 步，太粗）而否决。

### 开发历程

- 最初的版本"车子根本动都不会动"，于是把全车逻辑先放一边，写了一个**上电自检**：
  PC13 闪 3 下 → 四轮依次（左前→右前→左后→右后）各正转 0.3s / 停 / 反转 0.3s →
  四轮齐前进 / 后退 → 灯常亮。参数 `TEST_SPEED / TEST_RUN_MS / TEST_GAP_MS / TEST_WHEEL_GAP`。
- 自检暴露了两个真问题，靠"闪几下认轮子"一点点定位：
  - "闪1，2，4 都转，3 不行" → 某一路 PWM 没起来；
  - "右下方的轮子似乎是反的""两个前进都没有，两个后退都有" → **右后轮（RR）正反接反**，
    最后在 `motor_map` 里给该轮翻 `invert` 修正；
- 期间 CMake 一度被改坏，靠重新对齐 `cmake/stm32cubemx/CMakeLists.txt` 的源文件列表恢复构建。
- 第一次能跑起来时的体积：**FLASH 12064 B / 64KB（18.4%），RAM 1824 B / 20KB（8.9%）**。

## 麦轮逆运动学（全向移动）

### 功能描述

把"车要怎么走"（前后速度 `vx`、左右速度 `vy`、自转 `ω`）换算成四个轮子各自的速度：

```
FL = vx - vy - omega
FR = vx + vy + omega
RL = vx + vy - omega
RR = vx - vy + omega
```

工程上把教材里的 `(Lx+Ly)/R` 直接折进 `ω` 的量纲（`ω` 直接用"轮速"当单位），省一次浮点乘法——
**F103 没有硬件 FPU**，整数解算更快；四轮对称布置时 `(Lx+Ly)` 相同，不影响正确性。
`CHASSIS_SPEED_MAX` 取 800（小于 `MOTOR_SPEED_MAX` 1000），给三自由度叠加留等比缩放余量。

### 开发历程

- 10-11 22:50 用户：「先把那个全向移动做出来」→ 10-12 提交 `c858f51`（19 个文件，+1237/−553）。
- 同一轮把队友早期的 `chapter.c`、`mailun.c`、`servo.c` 删掉，`main.c` 瘦身 92 行，
  `ps2.c` 重写成能切模拟模式的完整驱动。
- 手感问题从这一版开始出现：摇杆前 40% 行程全死（没有死区外的补偿），后来在 `app.h` 里
  用 `APP_STICK_DEADZONE 12` + "死区外的部分再减掉死区"解决。

## 底盘从零重构（第二版 PWM 时基与占空比）

### 功能描述

10-19 车上加了配重，底盘表现全面变差，于是抛弃所有旧配速、从零重写（`chassis.c/h`、`motor.c/h`、`main.c`）：

- **PWM 时基改为 PSC=71 / ARR=49**：72MHz / 72 = 1MHz（一个计数 = 1µs），50 个计数 = 50µs = 20kHz。
  好处是占空比可以直接按 µs 算，调参时不用再换算。
- **满速占空比 `MOTOR_DUTY_PERCENT`**：先按要求的 40% 落地 → **实测四个轮子完全不动** → 临时提到 **80%**
  做测试，并在注释里写明"确认能转后再往回调"。
- 速度量纲统一为 `motor_set(轮号, -1000 ~ +1000)`，`MOTOR_SPEED_MAX = 1000`。

### 开发历程

02:27"四轮都不动"是这一天最大的坑，根因两条：① 40% 占空比在 8V 下等效电压太低（8V×32%≈2.56V）；
② 静摩擦。分别用"提占空比"和下面的"起步补偿"解决。

## 起步补偿（"踹一脚"）

### 功能描述

TT 电机静摩擦大，小占空比指令下不转。做法是在**起步瞬间**把占空比临时放大：

```c
MOTOR_KICK_MS   = 90     /* 起步补偿持续时间 */
MOTOR_KICK_GAIN = 200    /* 瞬间放大到 200%（仍钳在满速） */
MOTOR_KICK_MIN  = 450    /* 指令小于 450 不补偿，避免轻推摇杆一顿一顿 */
```

### 开发历程

- 02:56 用户要求「加一个起步时瞬时高电平突破启动」，先按 50ms / 80% 落地，
  实测后迭代成 90ms / 增益 200% / 阈值 450，最终固化为上面三个常量。
- 结论：起步补偿只解决"起不来"，不解决"走不快"，后者靠配速（下一板块）。

## 现场配速与整定（`tune` 旋钮）

### 功能描述

麦轮的纯横移混控是**四轮等幅**（FL−、FR+、RL+、RR−），一旦四个轮子的实际速度不一致，
差值会投影成自转分量——表现就是"横移画圈"。修法有两类旋钮，必须分开：

- **总速度**：四个轮子等比缩放，改的是快慢手感；
- **单轮补偿**：某个轮子单独加减，改的是"哪边偏"；
- **前后配平**：前一对 vs 后一对的差，改的是画圈的旋转分量。

最终输出：

```
PWM = 指令 × t_speed_scale/1000 × (1000 + 单轮补偿 + 前后配平 + 基准配速)/1000
```

现场调法见 `03-遥控与现场调参.md`。10-19 现场定下来的值：总速度 960‰、
单轮补偿 FL +80 / FR +40 / RL +200 / RR +140‰、前后配平 +30‰。

### 开发历程

- 10-17 第一次现场配速：早期四轮基准 `900/880/1050/1000`，现场改成 `850/850/1100/1100`。
- 10-17 14:06 定位"左右平移有问题"的真正原因——**右后轮机械装反**，"不是代码的问题"。
  修正后仍顺时针漂移，14:18 记录四轮速度排序「右上>左上>左下>右下」。
- 10-17 21:08 用户提出「能不能对每个轮子单独调优」→ 才有单轮补偿这一组按键。
- 10-19 重构后旧配速表作废，改为 `.persist` 段保存的"总速度 × 单轮补偿 × 前后配平"三旋钮，
  复位不清零、断电才丢；最终值再抄回 `tune.c` 的 `defaults_init()` 固化成上电起点。

## 底盘控制参数（现行）

| 参数 | 值 | 含义 |
|---|---|---|
| `APP_LOOP_MS` | 20 | 控制节拍 50Hz |
| `APP_SPEED_MAX` / `APP_SPEED_SLOW` / `APP_SPEED_MIN` | 800 / 400 / 250 | 平移速度上限 / 按住 L1 减半 / 最小可动速度 |
| `APP_TURN_MAX` / `APP_TURN_MIN` | 800 / 400 | 自转速度上限 / 下限（太低只嗡鸣不走） |
| `APP_RAMP_MS` | 250 | 斜坡时间（加减速不过冲） |
| `APP_STICK_DEADZONE` | 12 | 摇杆死区（PS2 中位 128） |
| `CHASSIS_SPEED_MAX` | 800 | 逆解后轮速上限（留叠加余量） |
| `MOTOR_PWM_PSC` / `ARR` | 71 / 49 | 1µs 步长、20kHz |
| `MOTOR_DUTY_PERCENT` | 80 | 满速占空比（40% 实测不动） |
| `MOTOR_KICK_MS` / `GAIN` / `MIN` | 90 / 200 / 450 | 起步补偿 |
