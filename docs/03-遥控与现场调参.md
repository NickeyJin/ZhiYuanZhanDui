## PS2 手柄协议（软件模拟 SPI）

### 功能描述

手柄是塔克创新 PS2 无线手柄（锁定款），接收器通过 6P 转接板接 MCU 四线：
PA4 DATA（MISO）、PA5 CMD（MOSI）、PA6 ATT（CS）、PA7 CLK——**全部用软件模拟时序**，
因为硬件 SPI 的时钟极性与帧间隔不好控。

- 一帧 **9 字节**；`buf[2] == 0x5A` 表示"数据来了"；
- 手柄 ID：`0x73` = 模拟红灯模式（有模拟量），`0x53` = 模拟绿灯模式，数字模式摇杆无模拟量；
- 掉线判定：无手柄时 DATA 上拉 → 全读 0xFF，所以 `ps2_buf[1] == 0xFF` 即为掉线；
- 位宽 **16µs**（`PS2_BIT_US`），必须用微秒级延时（见下条）。

### 开发历程

- 10-06 ~ 10-08 用两天时间做协议反查（当时"只讲解不改代码"，用户的原话是"我们现在在做一个小车…
  想学习如何用手柄去操控我的麦轮和一些舵机…最好是一步步教我"）：
  - 9 针定义 1-DATA / 2-CMD / 4-GND / 5-VCC / 6-ATT(CS) / 7-CLK / 9-ACK；
  - 6P 转接板正反两面引脚顺序**相反**（正面 GND VCC DAT CMD CS CLK，翻过来同一排是 CLK CS CMD DAT VCC GND），
    接线前必须确认；
  - ACK 脚在转接板上未引出，代码里不可能读 ACK（排除了一个常见排查方向）。
- 现场症状链：接收器"红灯快闪绿灯不闪"、用户自测"测试1：还闪 / 测试二：完全不动"、"完蛋是快闪"
  —— 全部指向"没进模拟模式 / 没配对"，最后确认要按住 MODE 键进模拟红灯模式。
- 产出 `_ps2_docs\PS2事实清单.md`（140 行，每条带出处）。

## 微秒级时基（DWT）

### 功能描述

`dwt_delay.c` 用 Cortex-M3 内核的 DWT 周期计数器做 `delay_us()`：

```c
CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
DWT->CYCCNT = 0;
DWT->CTRL  |= DWT_CTRL_CYCCNTENA_Msk;
/* delay_us(us): ticks = us * (SystemCoreClock / 1000000)，忙等 */
```

不吃定时器、不占中断，PS2 的 16µs 位宽就靠它。

### 开发历程

`HAL_Delay()` 只有 1ms 分辨率，喂不动 PS2 时序。10-10 写 `dwt_delay.c/h` 后，PS2 才第一次稳定握手。
另一个副作用是后来 `read_vars.ps1` 的 GDB 交互、`build\tools` 脚本都依赖这个稳定的微秒时基。

## 按键分工（人机交互）

### 功能描述

一套手柄、两个被控对象（底盘 + 机械臂），按键分工的原则是"**按住谁就走谁，不切模式**"：

| 按键 | 功能 |
|---|---|
| 左摇杆（只取主导轴） | 前后 / 左右平移，四个方向各占 90°，不斜走 |
| 右摇杆左右 | 原地自转 |
| 按住 L1 | 速度全减半（精细走位） |
| 按住 SELECT + ↑/↓ | 前后配平旋钮（见下） |
| 按住 SELECT + ←/→ | 总速度旋钮 |
| 按住 SELECT + L2/L1 + ←/→ | 单轮补偿：左前 / 左后 |
| 按住 SELECT + R2/R1 + ←/→ | 单轮补偿：右前 / 右后 |
| START | 急停（底盘停 + 机械臂松劲，灯慢闪） |
| SELECT + START | 机械臂四路通电 / 松劲 |
| ↑/↓、←/→、△/×、□/○、L1、R1 | 机械臂点动（见 04 篇） |
| R2 + R1 | 放块宏（见 04 篇） |

### 开发历程

- 10-16 20:25 起讨论"按键分布极简"。目标是一只手能开、另一只手偶尔点两下机械臂。
- 关键设计决策：**不做模式开关**。早期版本试过"L2 = 解算模式"这类切换，10-19 01:56 被否掉
  （"还是不要这个解算模式了"），原因是模式切换会让"按下去到底发生了什么"变得不可预测。
- 左摇杆只取主导轴、不斜走：斜走时四个轮子的合成速度难以预测，赛场上宁可直来直去。
- 10-19 22:48 精简后，所有"录制 / 回放 / 限位微调"的按键全部删除（见 04 篇），按键表收敛到上表。

## 现场调参旋钮（`.persist` 段）

### 功能描述

调参值放在链接脚本专门划的 `.persist` 段（RAM，NOLOAD）：**复位不清零，只有断电才丢**。
这正好匹配"赛场上反复试、懒得每次重烧"的用法。

| 变量 | 含义 | 范围 | 默认（现场定稿） |
|---|---|---|---|
| `t_speed_scale` | 总速度倍率（千分比） | 100 ~ 1250 | 960 |
| `t_wheel_delta[4]` | 单轮补偿（千分比，FL/FR/RL/RR） | ±600 | +80 / +40 / +200 / +140 |
| `t_trim_delta` | 前后配平 | ±300 | +30 |
| `t_fw_id` | 固件指纹 `0x4D454331`（"MEC1"） | — | 读到才说明烧的是开车固件 |

配套的结构体版本号 `TUNE_MAGIC = 0x54554E32`（"TNU2"）：变量增删时换掉它，上次留下的脏数据自动作废。

调完以后不必强记：`read_vars.ps1` 读回来，抄进 `tune.c` 的 `defaults_init()`，重编译烧录即固化。

### 开发历程

- 10-17 第一版只有 `SELECT + ↑/↓` 前后配平（每 250ms 一格、范围 ±300、掉电保存）。
- 10-19 02:45 用户要求"两组按钮分别调总速与左后轮"→ 03:00 细化成"四轮各自配速按键"，
  于是有 `SELECT + L2/L1/R2/R1 + ←/→` 的映射（左边两个键对左边两个轮子，一眼能对上）。
- 同一轮定下"每 250ms 走一格、一格 2%"的节流，避免手一抖调飞。
- 现场发现"每一档速度对应的最佳配比不一样"，所以这组旋钮**在正式版里保留**，不是临时调试开关。

## 灯语

### 功能描述

唯一的反馈通道是 PC13。三条原则：

1. **绝不在控制回路里用 `HAL_Delay()`**——20ms 的节拍被它一顶就爆，手柄直接掉帧
   （这是 `board.h` 里写死的注释："血的教训"）。所有闪烁都用 `HAL_GetTick()` 取模的非阻塞写法；
2. 上电签名为"闪 3 下"，代表初始化完成；
3. 运行中的含义：按按钮 = 快闪，只推摇杆 = 中闪，没碰 = 常亮，急停 = 慢闪。

### 开发历程

- 10-11 自检程序里 LED 承担了"报第几个轮子"的职责（闪 1/2/3/4 对应四个轮子），
  这套做法在排查右后轮接反时非常有效，直接沿用成习惯：**能用灯说清楚的，就不要靠猜**。
- 10-13 把灯态宏和非阻塞闪烁函数集中到 `board.h`；10-19 22:48 精简时并入 `tune.c` 的 `tune_led()`。
