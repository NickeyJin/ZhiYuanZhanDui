本板块完成于 10-06 ~ 10-11：主要测试PCB板能否使用、电机能不能转、手柄能不能读。后面所有衍生功能都基于这个板块。

## 主控与调试接口

### 功能描述

主控是 **STM32F103C8T6 最小系统板**。
板上只引出 **SWD**（PA13 / PA14）。因为电控组（me）没有USB-TTL，因此采用 `build\tools\read_vars.ps1` 通过 ST-LINK 读 RAM 里的变量来核对状态。（感谢DS对本次比赛的大力支持）

状态灯接 **PC13**（低电平点亮），相当于状态机的可视化。

引脚分配（CubeMX 里固定）：

| 功能 | 引脚 | 说明 |
|---|---|---|
| 电机 8 路 PWM | PA0/PA1（TIM2_CH1/CH2）、PA2/PA3（TIM2_CH3/CH4）、PB0/PB1（TIM3_CH3/CH4）、PA8/PA11（TIM1_CH1/CH4） | 3 片 DRV8833 双 H 桥，每轮两路 |
| PS2 手柄 | PA4 DATA、PA5 CMD、PA6 ATT、PA7 CLK | 软件模拟 SPI，16µs 位宽 |
| 舵机 4 路 | PB6/PB7/PB8/PB9（TIM4_CH1~CH4） | 50Hz，0.5~2.5ms 脉宽 |
| 状态灯 | PC13 | 低电平点亮 |
| 调试 | PA13/PA14 | SWD，禁止挪用 |

### 开发历程

- 10-06 16:45 由 STM32CubeMX 生成工程骨架；10-08 再生成 `stm32f1xx_hal_conf.h`、`main.h`。
- 选引脚时优先保证“电机 8 路 PWM 全在硬件定时器上”，所以 TIM1/TIM2/TIM3 全部交给底盘；
  10-15 机械臂接入时只剩 TIM4 可用，正好 4 个通道对应 4 个舵机——这也是后来舵机必须上 TIM4 的原因。

## 供电与共地

### 功能描述

电池为 **18650 ×2 串联（2S，标称 7.4V，满电 8.4V） **，分两条独立通路：

- **电机通路**：电池直接给 3 片 DRV8833 的 VM 供电（10-19 起改接 8V 档）；
- **舵机通路**：电池 → DC-DC 降压 5V → 四路舵机，舵机端并 470µF 电解。

两条通路独立，所以理论上，可以同时操作（实际上，至少人脑还没有办法同时处理这俩件事情，所以其实这个功能可能暂时没用？）

### 开发历程

- 10-16 讨论“能不能把小方块捡起来起来之后车的轮子依然可以动”时，确认了两条电源通路独立的方案。
  于是机械臂宏运行时底盘仍然可以走——这条结论直接决定了后来 `R2+R1` 放块宏可以“边放边走位”。

## 构建与烧录工具链

### 功能描述

不依赖 IDE，全部命令行完成，三个脚本在 `build\tools\`：

| 脚本 | 作用 |
|---|---|
| `direct_build.ps1` | 绕开 CMake 的 `try_compile`，直接调 `arm-none-eabi-gcc` 编译链接，默认产物 `build\direct\MyFirstCar.elf`；支持 `-ExtraDefines`/`-OutSub` 编变体固件 |
| `flash.ps1` | 调 `STM32_Programmer_CLI.exe`，ST-LINK + SWD 烧录并校验、复位 |
| `read_vars.ps1` | 起 ST-LINK GDB server + `arm-none-eabi-gdb`，**只读**地读 RAM 变量（复位不清的 `.persist` 段也能读） |

工具链：GNU Tools for STM32 **14.3.1+st.2**（ST 打包）。

### 开发历程

- 10-17 在和AI讨论了半天之后，确定了这两个脚本（`flash.ps1`、`read_vars.ps1`），虽然我的确没有看懂，不过的确达成了我的目的。
- 10-19 固定闭环：改代码 → `direct_build.ps1` → `flash.ps1` → `read_vars.ps1` 读回核对 →把现场实测值抄回头文件常量。当天几乎所有参数（限位、初始位、配速、占空比）都是这么定下来的。（还是很好用的！）
