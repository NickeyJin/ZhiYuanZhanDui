后面所有功能都长在这个平台上。

## 主控与调试接口

### 功能描述

主控是 **STM32F103C8T6 最小系统板**（LQFP48，72MHz，64KB Flash / 20KB RAM）。
板上只引出 **SWD**（PA13 / PA14），没有 USB-TTL，因此调试不靠 printf，而是：
板子跑起来 → 用 `build\tools\read_vars.ps1` 通过 ST-LINK 读 RAM 里的变量来核对状态。

状态灯接 **PC13**（低电平点亮），是这套系统里唯一的人机反馈通道，被定义为"灯语"（见 03 篇）。

引脚分配（CubeMX 里固定）：

| 功能 | 引脚 | 说明 |
|---|---|---|
| 电机 8 路 PWM | PA0/PA1（TIM2_CH1/CH2）、PA2/PA3（TIM2_CH3/CH4）、PB0/PB1（TIM3_CH3/CH4）、PA8/PA11（TIM1_CH1/CH4） | 3 片 DRV8833 双 H 桥，每轮两路 |
| PS2 手柄 | PA4 DATA、PA5 CMD、PA6 ATT、PA7 CLK | 软件模拟 SPI，16µs 位宽 |
| 舵机 4 路 | PB6/PB7/PB8/PB9（TIM4_CH1~CH4） | 50Hz，0.5~2.5ms 脉宽 |
| 状态灯 | PC13 | 低电平点亮 |
| 调试 | PA13/PA14 | SWD，禁止挪用 |

### 开发历程

- 10-06 16:45 由 STM32CubeMX 生成工程骨架；10-08 再生成 `stm32f1xx_hal_conf.h`、`main.h`。
- 选引脚时优先保证"电机 8 路 PWM 全在硬件定时器上"，所以 TIM1/TIM2/TIM3 全部交给底盘；
  10-15 机械臂接入时只剩 TIM4 可用，正好 4 个通道对应 4 个舵机——这也是后来舵机必须上 TIM4 的原因。
- 踩过的坑：`.ioc` 与代码不同步。10-15 机械臂接入后，"为什么不能配置 cmake 了"就是合并后
  `CMakeLists.txt` 源文件列表与 `.ioc` 不一致导致的，逐行对齐才恢复。之后约定：**引脚改动一律先改 `.ioc`
  再生成**，避免被 CubeMX 重新生成时冲掉。

## 供电与共地

### 功能描述

电池为 **18650 ×2 串联（2S，标称 7.4V，满电 8.4V）**，分两条独立通路：

- **电机通路**：电池直接给 3 片 DRV8833 的 VM 供电（10-19 起改接 8V 档）；
- **舵机通路**：电池 → DC-DC 降压 5V → 四路舵机，舵机端并 470µF 电解。

两条通路独立，所以"机械臂动的时候轮子照常能走"（这一点在 10-16 设计交互时被专门确认过）。

四条铁律（写在 `README.md` 与 `board.h` 注释里）：

1. 舵机红线**不许**接板载 3V3（MG995 堵转 1A+，会把 MCU 拉复位）；
2. 全系统共地；
3. 每片 DRV8833 的 nSLEEP 各用 10kΩ 上拉到 3V3（悬空 = 芯片休眠 = 轮子不动）；
4. PA13/PA14 是 SWD，别动。

### 开发历程

- 10-16 讨论"能不能把小方块 select 起来之后车的轮子依然可以动"时，确认了两条电源通路独立，
  于是机械臂宏运行时底盘仍然可以走——这条结论直接决定了后来 `R2+R1` 放块宏可以"边放边走位"。
- 10-18 的固件变体（舵机单独测试固件）曾用板载 5V 给舵机供电，出现复位/掉线，最终固化为"舵机独立 5V"。

## 构建与烧录工具链

### 功能描述

不依赖 IDE，全部命令行完成，三个脚本在 `build\tools\`：

| 脚本 | 作用 |
|---|---|
| `direct_build.ps1` | 绕开 CMake 的 `try_compile`，直接调 `arm-none-eabi-gcc` 编译链接，默认产物 `build\direct\MyFirstCar.elf`；支持 `-ExtraDefines`/`-OutSub` 编变体固件 |
| `flash.ps1` | 调 `STM32_Programmer_CLI.exe`，ST-LINK + SWD 烧录并校验、复位 |
| `read_vars.ps1` | 起 ST-LINK GDB server + `arm-none-eabi-gdb`，**只读**地读 RAM 变量（复位不清的 `.persist` 段也能读） |

工具链：GNU Tools for STM32 **14.3.1+st.2**（ST 打包）。

### 开发历程

- 10-17 19:22~19:38 两个脚本（`flash.ps1`、`read_vars.ps1`）并行产出。烧录前先整片备份
  `build\direct\flash_backup_before_ps2test.bin`（131072 B）。
- 脚本强制纯 ASCII：Windows PowerShell 5.1 按 GBK 读 `.ps1`，中文注释会破坏解析。
- 10-19 起形成固定闭环：**改代码 → `direct_build.ps1` → `flash.ps1` → `read_vars.ps1` 读回核对 →
  把现场实测值抄回头文件常量**。当天几乎所有参数（限位、初始位、配速、占空比）都是这么定下来的。
- 一个必须记住的坑：链接用了 `--gc-sections`，**"代码里没人引用"的全局变量会被直接删掉**，
  第一次写的固件指纹变量压根没进符号表。解决办法是在代码里给它赋一次值（并加 `volatile`），
  再放进 `.persist` 段（`KEEP` 保住）。
